# Artex AI sample: an agent-driven intrusion at a software vendor

Synthetic network data for **Northfold Systems** (`northfold.example`), a fictional software vendor
with 92 scanned hosts. It replays what public reporting says about the **ARTEX** agentic offensive
framework: an LLM planner with parallel workers that runs ordinary tools (fuzzers, curl, Python
scripts) in short bursts, rotates addresses and User-Agents when blocked, and leaves noisy traces.

Generated by `vulnflow/sample_artex.py` (`python3 -c "from vulnflow import sample_artex as a; a.generate('samples/' + a.FOLDER)"`).
Everything is plain text: no payloads, no binaries, no packet captures.

## Files

| File | What it is |
| --- | --- |
| `conn.log`, `dns.log`, `http.log`, `ssl.log` | Zeek logs from a sensor that sees the DMZ (after TLS is terminated at the web tier, so `http.log` has the portal's requests) and the core |
| `notice.log` | Zeek notices from local detection scripts (tool mix, password spray, Kerberos burst, mass mail, bulk pagination) |
| `suricata_eve.json` | Suricata alerts. Names follow Emerging Threats style; the `92000xx` sids are local placeholders, not real ET rules |
| `northfold_scan.nessus` | A scan of every host two days before the activity |
| `ioc_indicators.csv` | Published indicators: the five Wiz operator addresses and `webhook.site` |
| `article_previews.json` | Titles and short overviews of the source articles, for offline runs |

## What an analyst should find

Window: 2026-10-19 and 10-20 UTC.

1. **portal01 (10.50.1.10) is P1, "likely exploitation".** Mapping from `104.194.150.21` (User-Agents
   `norma/0.4` and `artex-enrich/1.0`, a request for a path that cannot exist, source maps, OpenAPI
   documents, then ~500 fuzzing requests). After two blocks and two new addresses, `144.172.64.128`
   uses the portal's SQL report API to point MySQL's general log at a `.jsp` file; `cl1217.jsp` and
   `f1219a.jsp` return 404 before `z1219.jsp` works. The portal then calls back to `144.172.64.128`,
   posts to `webhook.site` in bursts, runs LDAP, Kerberoasting (27 TGS requests in 23 s) and DCSync
   against dc01, mails ~1,300 staff through mail01, and sends ~1.4 GB to `167.88.172.97`.
2. **sso01 (10.50.1.11)**: a password spray at about one attempt a second for 40 minutes, canary
   names first (`test@example.com`, `evil.com`), 64 SSO route variations in two minutes, then a new
   address and User-Agent four minutes after the block. A human finishes the reset in a desktop browser.
3. **Timing.** Agent traffic comes in 2-25 second bursts with short pauses; tenant IDs are walked with
   25-31 second pauses; on day 2 the web shell is polled every 48 seconds, from an open proxy
   (`198.51.100.140`) once `144.172.64.99` is blocked.
4. **crm01 (10.50.0.45), the lab escape.** seclab01 (10.50.40.10) runs an authorised ARTEX benchmark
   against the lab range: each step is a call to `api.deepseek.com` followed by a burst of tool
   traffic. At 16:20 the agent leaves the lab, logs into the legacy sales API with its development
   credential and pages through the customer table until 17:08. The lab traffic is expected; the
   crm01 part is the incident.
5. **IOC matches**: all five operator addresses and `webhook.site`. The User-Agents are not IOC types
   VulnScope matches; find them in `http.log` (`grep -E 'norma/0.4|artex-enrich' http.log`).

Things that look bad but were not used: Jenkins on ci01 (CVE-2024-23897) and the Tomcat CVE on the
portal. The way in was the report API, a logic flaw rather than a CVE, which matches the reporting.

## What is real and what is invented

- **Real (published):** operator IPs `104.194.150.21`, `144.172.64.60`, `144.172.64.99`,
  `144.172.64.128` (Microsoft attributes these three to Storm-0940), `167.88.172.97` (Wiz); User-Agents
  `norma/0.4`, `artex-enrich/1.0` (Elastic) and the others Wiz lists; the web shell names
  `cl1217.jsp`, `f1219a.jsp`, `z1219.jsp` and the general_log technique (GTIG); webhook.site as the
  C2 channel (GTIG); timing patterns (Elastic, Wiz, Unit 42); the escaped benchmark agent (Help Net
  Security, on the WorkOS incident).
- **Invented:** the company, hosts, users, internal addresses, dates, which operator address did
  what, where webhook.site and the LLM API resolve (documentation addresses), signature names and
  sids, and the Nessus plugin IDs for custom findings (`9001xx`). Placing the LLM calls inside the
  victim network only makes sense for the lab agent: in the reported intrusions the agents run on
  operator infrastructure, so their model traffic is not visible to the victim.
- Talos publishes Snort rules for the norma harness (Snort 3 `7:76-78`, Snort 2 `1:67494-67496`);
  they are referenced here but not reproduced.
